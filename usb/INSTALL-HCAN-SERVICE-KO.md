# HCAN 서비스 구현 보완 추출 v0.3.1

이 ZIP은 **추가 분석 파일 세 개를 확인하는 수집 도구**입니다. 배기 플랩 제어 패키지가 아닙니다. 한국 CN7N PE `V039.001.260902`, TCC803x와 기존에 정상 실행되는 NEMESIS 환경만 지원합니다.

## 사용하는 방법

1. 릴리스의 `NEMESIS-CN7NPE-Exhaust-HCAN-Service-Research-v0.3.1-USB.zip`을 내려받습니다. GitHub의 Source code ZIP과 다릅니다.
2. ZIP의 모든 파일을 USB 최상위에 풉니다. 기존 USB의 `NEMESIS.data`와 수집 스크립트는 먼저 PC에 보관하거나 별도 USB를 사용하세요. `progress.sh`도 필요합니다.
3. 주차 상태에서 내비 부팅 후 데이터 USB 포트에 연결하고 NEMESIS의 스크립트 실행 질문에 동의합니다.
4. 화면의 퍼센트·단계·현재 파일을 확인합니다. 파일 크기 확인은 각 15초, 복사는 각 60초, USB 저장 마무리는 60초 제한입니다. 일반적인 예상 시간은 약 30초~2분이며 USB 상태에 따라 달라집니다. 진행률은 작업 단계 기준이고 남은 시간이나 바이트 전송률이 아닙니다.
5. **100% 이후 NEMESIS 완료 알림까지 확인한 다음** USB를 분리합니다. 실패하면 결과 폴더를 그대로 보관하세요.
6. 새로 생성된 `CN7NPE-exhaust-private-N` 폴더만 PC 프로젝트의 `private` 아래에 복사하고 위치를 알려 주세요. 기존 결과와 섞지 마세요. 같은 이름의 결과를 덮어쓰지 않으며 최대 20개까지 새 폴더를 사용합니다.

`result.txt`의 `collection=COMPLETE`와 `report.txt`의 `service_jar=1`, `service_odex=1`을 확인하면 필수 파일 수집이 완료된 것입니다. `jni_library=0`은 선택 라이브러리 누락이며, 그것만으로 실패하지는 않습니다. 누락·크기 제한·복사 오류는 보고서에 남습니다. 필수 파일이 없거나 제한을 넘으면 100% 완료로 표시하지 않습니다.

## 수집하는 파일과 근거

| 경로 | 필요 이유 | 구분 |
| --- | --- | --- |
| `/system/framework/com.infobank.jar` | 기존 framework2의 Loader가 지정한 HCAN 서비스 구현 컨테이너 | 필수 |
| `/system/framework/com.infobank.odex` | ODEX 분리 배포에서 실제 코드 분석에 필요. 기존 파일 목록에서 존재 확인 | 필수 |
| `/system/lib/libautoframework_jni.so` | 같은 Loader의 Infobank JNI 경로가 가리키는 라이브러리 | 선택 |

파일당 8MiB, 복사 합계 16MiB로 제한합니다. 심볼릭 링크는 따라가지 않습니다. 필수 파일이 제한보다 크면 부분 결과만 보관하고 중단합니다. 이때 큰 파일을 임의로 다시 수집하지 말고 보고서를 전달해 주세요.

이미 받은 N 모드 APK, HCAN 확장, Engineering Mode, `micomd/hscand/micomlog`는 다시 복사하지 않습니다. 디렉터리 전체 검색, 프로세스·서비스 목록 재수집, `/data`·개인정보·차량 로그·MICOM 플래시/펌웨어 덤프도 수행하지 않습니다. 제품과 플랫폼 속성 두 개를 확인하고, 지정 파일과 크기를 읽어 USB의 새 폴더에 씁니다. NEMESIS 진행 화면 호출 외에 차량 Binder 호출·통신 소켓 연결·명령 송신·시험 모드·데몬 시작/중지는 없습니다. 복사한 파일도 실행하지 않습니다.

이번 분석으로 확인하려는 것은 `TM_HSCANService` 내부의 진단·신호 설정 처리와 MICOM으로의 전달 방식입니다. **이 파일을 확보해도 MICOM 펌웨어 내부나 AEV 개폐 명령이 반드시 밝혀지는 것은 아닙니다.**
